# Quick 261105-v1e: log real-time data source candidates with measured volume

Outcome: a JSONL manifest of every candidate source considered for the data-engineering extension, each with a
measured volume (or an explicit "not measured"), so a low-volume source stays on record without being discussed again.
Use: pick the project's source by volume and fit; remember what was already ruled out and why.

Mode note: the quick workflow's planner and executor subagents were not spawned. The task is two docs files and the
measurements were already taken in this session, so the orchestrator wrote the plan and ran the task inline.

## Files

- docs/data-engineering-extension/source-research/sources.jsonl (one `source` record per line)
- docs/data-engineering-extension/source-research/README.md (record shape, volume classes, how it was measured)

## Alternative approaches considered

1. DuckDB table with a `.sql` schema (global rule R51 prefers DuckDB for research stores).
2. One JSONL file, one flat record per source, volume embedded as an object.
3. A markdown table in DESIGN.md.

| Approach | Pros / Cons | Why picked |
| --- | --- | --- |
| DuckDB table + schema SQL | Typed, constraint-checked, queryable. Needs a binary file or a build step for about 27 rows; the user asked for JSONL | Not picked: the user named JSONL, and `duckdb` can read the JSONL in place when a query is wanted |
| JSONL, flat record, embedded `volume` object | Appendable, diffable, `jq`-queryable, matches R26. Volume is a keyed measurement set read with its source and never queried alone, so embedding it avoids a child table | Picked |
| Markdown table | Readable, but no schema, columns drift, nothing validates it | Rejected |

Trade-offs: the volume measurement is a single as-of snapshot per source (15 to 60 s windows on one evening), not a
distribution. Diurnal swings are unmeasured, so every `events_per_sec` is a point sample. A re-measurement is a new
`measured_on` date on the same record, not a new row; history would need a second file if it ever matters.

Entities: 1 (`source`). `tables: 3 -> 1`: no `publisher` table (one publisher per source, no attributes of its own),
no `measurement` table (one snapshot per source, read with it), no `protocol` lookup (closed set of 7 values, an
enum in the README).

## Tasks

1. Write sources.jsonl, ordered by `volume.events_per_sec` descending, nulls last.
2. Write README.md with the record shape and the measurement method.
3. Validate with jq: every line parses, ids unique, required keys present, enums in range, order holds.
4. Commit only these two files and the quick-task directory, `--no-verify` (docs-only, allowed by CLAUDE.md).
