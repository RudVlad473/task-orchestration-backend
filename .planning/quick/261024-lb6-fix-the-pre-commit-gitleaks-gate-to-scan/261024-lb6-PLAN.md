<objective>
Make the pre-commit secret scan read the index that `git commit` is about to record, so a credential
in an unstaged edit committed by `git commit -- <paths>` (or `git commit -a`) is refused. Pin the
fix with a selftest that fails against HEAD's hook and passes against the fix.

Outcome and use: after this lands, every commit made in this repo is scanned on the bytes it will
actually contain, whatever commit shape the committer or an agent uses. The selftest in CI keeps it
that way.

Purpose: since the hook was written, every pathspec commit of unstaged edits (the shape the user's
global rules prescribe) has scanned about 0 bytes and printed "no leaks found".
Output: scripts/pre-commit-gitleaks-selftest.py, a fixed .githooks/pre-commit, one new job in
.github/workflows/invariant-checks.yml, and the SUMMARY.

## Measured during planning (2026-10-24; do not re-litigate)

Measured in throwaway repos under /tmp with the pinned image. The tested hook was the real HEAD
.githooks/pre-commit, with its later gates stubbed to exit 0.

What git exports to the hook, by commit shape:

| Shape | GIT_INDEX_FILE seen by the hook | GIT_DIR |
|---|---|---|
| plain staged `git commit` | `.git/index` (RELATIVE, hook cwd = work tree root) | unset |
| `git commit -- <paths>` (also from a subdir) | absolute `<repo>/.git/next-index-<pid>.lock` | unset |
| `git commit -a`, `git commit -i <paths>` | absolute `<repo>/.git/index.lock` | unset |
| nested worktree `.claude/worktrees/wt`, pathspec | absolute `<repo>/.git/worktrees/wt/next-index-<pid>.lock` | absolute, set |
| out-of-tree worktree, pathspec | absolute `<repo>/.git/worktrees/oot/next-index-<pid>.lock` | absolute, set |
| hook run by hand | unset | unset |

Verdicts per commit shape (HEAD hook vs the two prototypes). Bytes come from gitleaks' `scanned ~N bytes` line:

| Shape | HEAD hook | Fix A prototype | Fix B prototype |
|---|---|---|---|
| staged leak, plain commit | refused, 47 B | refused, 47 B | refused, 162 B |
| unstaged leak, `-- leak.txt` | COMMITTED, 0 B | refused, 47 B | refused, 162 B |
| unstaged leak, `-a` | COMMITTED, 0 B | refused, 47 B | refused, 162 B |
| unstaged clean edit, `-- a.txt` | committed, 0 B (false clean) | committed, 5 B | committed, 108 B |
| nested worktree, unstaged leak, pathspec | COMMITTED, 0 B | refused, 47 B | refused, 162 B |
| out-of-tree worktree, unstaged leak, pathspec | refused, 260 B (stdin branch) | refused, 162 B | refused, 162 B |
| GIT_INDEX_FILE outside the repo, leak staged in it | not measured (predicted COMMITTED) | refused, 162 B (stdin fallback) | not measured |
| fix A with a space in the repo path | n/a | all of the above identical | n/a |

Where A and B differ, measured on a repo whose committed file already held a credential:

| Commit | Fix A | Fix B |
|---|---|---|
| edit the line next to the committed credential | allowed | REFUSED (context lines are scanned) |
| delete the committed credential | allowed | REFUSED (removed lines are scanned) |
| new leak: does the finding print a `File:` line | yes, `File: new.txt` | no File line at all |

Two further facts:
- The out-of-tree stdin branch was already correct on HEAD. Its `git diff --cached` runs on the host and inherits GIT_INDEX_FILE. Only the bind-mount branch is broken.
- Gitleaks colours its log lines even when writing into a pipe. Strip ANSI escapes before parsing `scanned ~N bytes`.

`git commit -a` and `-i` were not in the brief. They are the same hole: git writes `index.lock` and
the hook reads `.git/index`. The fix covers them, and the selftest pins `-a`.

## Approaches considered (project directive: 2 alternates + trade-off matrix)

| Approach | Pros/Cons | Why Picked |
|---|---|---|
| A: forward GIT_INDEX_FILE into the container, translated to `/repo/<rest>` when it lies under MOUNT_ROOT; an index outside the mount, or one that fails to resolve, takes the existing stdin shape | Pro: one shape for every in-tree commit; keeps `git --staged` semantics (scans added lines only, keeps `File:` attribution, path-scoped allowlists stay possible); unset case is byte-identical. Con: path resolution must handle relative and absolute paths and symlinks. A miss falls to stdin, which still scans the right index, so a miss loses attribution but never coverage | PICKED: refused all five leak shapes and kept today's behaviour for deletion and adjacent edits (measured above) |
| B: whenever GIT_INDEX_FILE is set, pipe `git diff --cached` into `gitleaks stdin` | Pro: no path translation. Con: git sets GIT_INDEX_FILE on EVERY commit (measured), so B moves every commit off the bind mount, and that branch becomes reachable only by hand. It refuses deleting a committed credential and editing beside one, so it blocks a leak's own remediation. Findings lose the `File:` line that the refusal message points at, and path-scoped allowlists cannot match | Rejected on the measured costs |
| C: stop using pathspec commits in this repo | Leaves `-a`, `-i` and any tool that supplies its own index unscanned, and depends on every committer remembering | Rejected (brief) |

Trade-offs that are not obvious:
- Performance: unchanged. It is still one container run per commit, with the same image. The selftest adds one commit and one container run per case (seven).
- State: the temporary index is a lock file that git deletes after the commit. The container reads it while git holds it, for as long as the hook runs, and that read was measured working.
- Security: the new input is an environment variable, passed as one quoted docker argument and never evaluated. A bogus path under the mount makes gitleaks error out, which the hook's existing three-way exit contract (anything else = "could not run", commit refused) already turns into a refusal. A path outside the mount takes the stdin shape. Neither fails open.

Data flow (3 sentences): `git commit` writes the index it is about to record (`.git/index`, or a
temporary `next-index-<pid>.lock` / `index.lock` for pathspec, `-a` and `-i`) and exports its path
to the hook as GIT_INDEX_FILE. The hook bind-mounts the repo at /repo and runs gitleaks
`git --staged`, whose internal `git diff --staged` reads whatever index GIT_INDEX_FILE names, so the
fix translates that path into /repo and forwards it. When the index is outside the mount, the hook
pipes a host-side `git diff --cached` (which reads GIT_INDEX_FILE itself) into `gitleaks stdin`.
