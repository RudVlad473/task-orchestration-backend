## Decision for the user: pin docker/* too?

Pinning docker/setup-buildx-action and docker/build-push-action by SHA is two lines in deploy.yml, and Dependabot's github-actions entry keeps the SHAs current. For: both run in the job that has Docker Hub push credentials in the runner, and Flux deploys the tags it pushes, so a compromised action could ship an image. Against: deploy.yml records an explicit risk acceptance for them, and a SHA pin means a Dependabot PR per release. Recommendation: pin them, since the blast radius is production. I left them unchanged because the plan scoped pinning to the write-scoped token; if you say nothing, they stay as they are.
