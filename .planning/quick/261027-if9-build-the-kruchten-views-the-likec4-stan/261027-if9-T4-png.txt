== what I saw (each PNG opened with the Read tool, downscaled to 2000 px wide; I had no crop tool)
signin-ok: five lifelines left to right: Browser / API client, Traefik, REST API, users (cylinder), spring_session (cylinder,
  its box reads "Authored. Spring Session creates this table at startup (initialize-schema=always), outside Flyway.").
  Nine numbered steps: 1 POST /api/signin {email, password} client to Traefik; 2 forward Traefik to REST API; 3 SELECT user
  by email REST API to users; 4 row, users back to REST API; 5 SELECT user by id to users; 6 read live sessions for the
  user to spring_session; 7 rotate session id, save security context to spring_session; 8 200 Set-Cookie JSESSIONID REST
  API back to Traefik; 9 200 {id, email, displayName, theme} Traefik back to the client. Matches step 4 of the plan.
signin-bad-credentials: four lifelines (client, Traefik, REST API, users). Six steps: POST, forward, SELECT user by email,
  no row (users back to REST API), 401 BAD_CREDENTIALS (REST API to Traefik), 401 ProblemDetail, code BAD_CREDENTIALS
  (Traefik to client). Matches the plan.
signin-ceiling: the five lifelines of signin-ok. Steps 1 to 6 as signin-ok, then 7 ceiling reached (spring_session back
  to REST API), 8 401 BAD_CREDENTIALS, 9 401 ProblemDetail, code BAD_CREDENTIALS. Matches the plan.
