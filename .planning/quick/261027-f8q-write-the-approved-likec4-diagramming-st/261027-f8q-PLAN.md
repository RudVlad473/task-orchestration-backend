## Non-obvious trade-offs

1. **The guard is already red.** A plan that demanded exit 0 would force a fix to an unrelated
   docs/learning file. Instead, the whole output and exit code are diffed against a baseline taken
   before any edit. A crash or a new violation changes the output, so it cannot hide behind the old exit 1.
2. **The guard has a blind spot that this plan must not lean on.** A `.c4` path under the docs diagram
   folder would never be flagged, because the token regex accepts only .mmd, .png and .svg. The hazard
   is avoided by a rule (the section names no path under that folder), backed by a region-scoped
   negative grep, not by trusting the guard.
3. **State invalidation: the wiki copy goes stale.** `docs/wiki/conventions/diagram-conventions.md` will
   lag this edit. .claude/CLAUDE.md makes the originals authoritative until a cleanup deletes them, and
   the wiki lint does not compare copies. This plan must not touch the copy, so the lag is recorded in
   the SUMMARY.
4. **Number provenance.** The brief's `process 1233` comes from spike 006's render. The verify workspace's
   re-render of the same view is 1254. Both fail the 1117 bound, but the section names the source of
   each, and the SUMMARY records 1254 as 2508 / 2.
5. **Security.** `--no-verify`, which .claude/CLAUDE.md allows for docs and planning commits, skips the
   hook's gitleaks scan. Both commits therefore run the hook's own pinned gitleaks image on the staged
   diff first, because this change adds roughly 20 new files.
6. **Performance and memory:** none at runtime. The doc grows from about 14 KB to about 25 KB. It is read
   on demand and is not always-loaded, so the instruction budget is unchanged.
7. **The index is shared (SESSION_LESSONS lesson 2).** Other quick tasks' untracked files sit in this tree
   (261024-nvj, 261024-q91, and this directory's own PLAN.md). Stage named paths only and read
   `git diff --cached --name-only` before every commit.

## Data flow of the guard check

The guard lists tracked files with `git ls-files` and opens each one from the working tree. It pulls
diagram-path tokens out of link targets, src attributes and code spans outside fenced blocks, and it
prints one line for every token that does not resolve, followed by a summary line. Diffing that output,
plus the exit code, against the pre-edit baseline isolates what this change added. Deleting the section
and diffing against the base commit proves that no existing line changed.
