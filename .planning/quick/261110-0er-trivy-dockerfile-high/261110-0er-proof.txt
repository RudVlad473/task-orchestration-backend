Handoff for 261110-0es (evidence only, no manifest edited)
-----------------------------------------------------------
Same placeholder environment, image kanban-0er-probe:local, run to exit and read from the logs:
- docker run --read-only (no tmpfs): startup FAILS before the database is reached. First ERROR is "Application run failed",
  ApplicationContextException "Unable to start web server"; the cause text is "Unable to create tempDir. java.io.tmpdir is
  set to /tmp" with "Read-only file system" (1 occurrence).
- docker run --read-only --tmpfs /tmp: startup gets as far as without the flag: 0 "read-only file system" lines, and the first
  ERROR is the entityManagerFactory failure from "Connection to 127.0.0.1:5432 refused".
So a read-only root filesystem without a /tmp mount breaks startup (Tomcat temp directory). A readOnlyRootFilesystem: true
in k8s/base/app/app.yaml needs an emptyDir at /tmp for the app container. This was measured with docker's --tmpfs, which
is not the same as a kubelet emptyDir (ownership and mode of an emptyDir come from the kubelet, fsGroup and the runtime);
the register-schemas initContainer was not run read-only. If 0es pins a uid, use 65534.

Not verified without a cluster
------------------------------
- Volume ownership and fsGroup: the manifest mounts no volume, so this is a statement about the manifest, not a run.
- That kubelet accepts runAsNonRoot: true against the numeric 65534:65534 user:group form: not run, no cluster. The
  numeric form is the documented reason for choosing it.
- How any runAsUser, fsGroup or readOnlyRootFilesystem that the sibling items add interacts with uid 65534: not run.
  Only the docker --read-only and --tmpfs probes above exist.
- A full start against real Postgres and Redpanda: the probe reaches only the first refused database connection, so any
  later startup write (after the database is up) was not seen.
- The rollout under the Recreate strategy: not run. A crash on start is an outage until a rollback.
- That the image CI builds equals this one: the probe was built locally from the same Dockerfile and the same
  `docker build --pull`; the CI build was not run and the base digest can differ over time.
