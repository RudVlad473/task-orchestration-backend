## Root cause of the 0-dependency scans

Spring Boot 3.5.16 makes runtimeClasspath extend testAndDevelopmentOnly. dependency-check-gradle 12.2.2 tests the configuration name and every
name in its hierarchy against a "test" regex and skips a match when `skipTestGroups` is true (the default). So the only configuration named in
`scanConfigurations` was skipped. Evidence, local and offline before the fix, at `--info`: `'runtimeClasspath --> runtimeOnly --> implementation
--> developmentOnly --> testAndDevelopmentOnly' is considered a test configuration: true`; the line is absent after the fix. In CI the same
workflow went from 0 entries (2026-08-19) to 171 (run 40103131374). A second failure sat under it: the 2026-08-19 update thread died of an
OutOfMemoryError 15 seconds in while the build still ended BUILD SUCCESSFUL; the scan steps now run with a 3g daemon and the step fails on that string.

(1) triage the findings above into real and false, and suppress the false ones with the evidence cited (the opentelemetry-js match on Java jars and

version); (2) re-run the scan; (3) if the 2 spring-webmvc criticals are the only critical findings left, a critical-only rung (`failBuildOnCVSS = 9`)
