== KSV-0109 evidence
(a) Row: Title "ConfigMap with secrets", Description "Storing secrets in configMaps is unsafe", Resolution "Remove password/secret from
configMap data value", Message: ConfigMap 'postgres-init-62tc4bg5h4' in 'kanban-data' namespace stores secrets in key(s) or value(s)
with six matched fragments: an empty string, `-v monitoring_pass`, `-v nonprod_pass`, `-v prod_pass`, `CREATE ROLE `,
`CREATE ROLE monitoring WITH LOGIN PASSWORD `. The matches are keywords and variable names, not values.
(b) Data of the rendered ConfigMap postgres-init-62tc4bg5h4 (two keys, 01-create-databases-and-roles.sh and
02-create-monitoring-role.sh): 112 lines. Lines matching `pass` case-insensitively (the repo's own script text):
   16  : "${PROD_DB_PASS:?PROD_DB_PASS must be set}"
   19  : "${NONPROD_DB_PASS:?NONPROD_DB_PASS must be set}"
   43  # password happens to be generated is load-bearing any more (closes ... review reference ...)
   53      -v prod_pass="$PROD_DB_PASS" \
   56      -v nonprod_pass="$NONPROD_DB_PASS" \
   58      CREATE ROLE :"prod_user" WITH LOGIN PASSWORD :'prod_pass';
   63      CREATE ROLE :"nonprod_user" WITH LOGIN PASSWORD :'nonprod_pass';
   91  : "${MONITORING_DB_PASS:?MONITORING_DB_PASS must be set}"
   98  # as received, so no assumption about how a password happens to be generated is load-bearing.
  104      -v monitoring_pass="$MONITORING_DB_PASS" \
  107      CREATE ROLE monitoring WITH LOGIN PASSWORD :'monitoring_pass';
(c) Classification: 11 matching lines = 2 comments (43, 98), 3 `${NAME:?...}` guards (16, 19, 91), 3 `-v name="$NAME"` arguments
(53, 56, 104) and 3 psql `PASSWORD :'name'` references (58, 63, 107). The filter removing those four shapes leaves residue 0 lines.
(d) The render of the postgres root has no Secret object (yq select(.kind=="Secret") printed nothing) and
`rg -n '^kind: Secret' k8s -g '*.yaml'` found none (exit 1). The manifest comment in postgres.yaml says of the postgres-init
Secret: "Created on the VM from env files, never committed."
(e) The only root with a KSV-0109 row is k8s-data-postgres.yaml (jq over every Target). k8s/data/postgres/kustomization.yaml
holds the configMapGenerator (postgres-init from the two init scripts, postgres-backup-script from the backup script); it
holds no secret and is unchanged.
Decision: keyword match on variable names, a false positive. Nothing is moved to a Secret. Rule R4 not triggered.
