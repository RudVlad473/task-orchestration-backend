## Regression test: why none

The basis is the user's global `~/.claude/CLAUDE.md`, not a project rule; no project file (CODE_STYLE.md, DIAGRAM_CONVENTIONS.md, SESSION_LESSONS.md, `.claude/CLAUDE.md`) says anything about tests for prose. Two of its rules apply:
- "Pin every bug fix with a test that fails without it": add a test unless the answer is genuinely no, run it red against the unfixed code and green against the fix, and write it at the layer where the bug lived.
- "Code is a liability": tests are never for what is meant to keep changing (a docs layout, a file inventory), because each legitimate edit fails them.

The bug lived in model prose, and no gate reads prose. `sync.mjs check` validates LikeC4 syntax and drift rules over element metadata (`workload`, `source`, `host`) and the titles of topic and namespace nodes, never a description or a relationship title (`rg` over sync.mjs, 2026-10-29), so a standing test means the first prose-reading rule in `sync.mjs` (approach 2). That rule could hold only the workflow-name lists on delivery.c4:7 and :42. The "only job of this workflow" claims on scenarios-platform.c4:33 and :38 are semantic, and no string match holds them. For the half it could hold, the rule keys on wording: a rewording that names the workflows another way fails it, and wording is what the second rule exempts. Its one real benefit, failing when a fourth image-pushing workflow lands without a model change, is the residual risk accepted in T-03-32. So: no standing test. This is a judgment against the first rule's default, made on these stated grounds; no rule forbids such a test.

The fix is still checked in both directions, once. Every set diff, absence search, row 4 gate and build gate in the verify blocks was run red against HEAD at planning time (baselines recorded beside each), and the executor runs them green after the edit. On 2026-10-29 both new gates were also run green against this plan's exact edits:
- The row 4 gate passed on scratch copies of the evidence file and scenarios-platform.c4 carrying the planned row and step. It failed on a copy with one quote altered, on one with the old step text, and on the new row beside the unedited model.
- The build gate passed with the six model edits applied in place (restored from HEAD afterwards), at new_files 3, 2, 4, 4, 5 and 6 for L38, L33, L7, L14, L42 and L43. That run used an earlier form that took new/old pairs. The final label/new/old form was then re-run: red at HEAD, green on a control set of phrases, red when one old phrase was left in the build. It also refused to run over an existing `docs/architecture/site/out`, and deleted nothing. That is a one-shot proof, not a regression guard. What a guard would need is approach 2's list: a `sync.mjs` rule that reads `push: true` from `.github/workflows/*.yml` and the `.yml` names from delivery.c4:7 and :42, a drill row, a regenerated `drill-output.txt` and a hook selftest case. ## Non-obvious trade-offs
- **Security:** the reworded step publishes the token's real reach: the production-environment jobs of three workflows. The workflow files are public, so nothing new is disclosed. The new text is also the accurate statement: the two-job split fences the token within this workflow, not across the repository.
- **State invalidation:** `sync.mjs check` never reads prose (LikeC4 validates syntax and the drift rules only). The evidence row is the only standing tie. No row of `docs/architecture/drills.tsv` touches any of the six edited lines (`rg` over drills.tsv, drill.fish and sync.mjs found nothing), so the drill replay is not re-run.
- **Live site lags the commit:** the staging host serves the old sentences until a push to main. That push starts `architecture-site.yml` (`docs/architecture/model/**`, lines 24-28) and not `deploy.yml` (`docs/**` and `.planning/**` are in its `paths-ignore`, lines 18-21). It costs one site run and one Flux bump, and it carries the 6 local commits already ahead of origin/main at planning time. This plan does not push: that is the user's call.
- **Rendered size:** step 4's label grows, and so do the delivery view's :42 and :43 edge labels. DIAGRAM_CONVENTIONS.md records publish-the-site at 2360 x 1401 and delivery at 2342 x 1573, both dated 2026-10-28, without a verdict, and the legibility rule is undefined. They are not re-measured here, and the SUMMARY says so.
- **Performance and memory:** none at runtime. Each build gate takes about 10 s (measured at planning time) and writes about 6.7 MB to the gitignored `docs/architecture/site/out`, then trashes it. Each task runs its gate twice, once before committing and once as the verify, so about 20 s per task. Building inside the verify costs that time, and in exchange no BUILT claim rests on the executor's record.
- **`--no-verify`:** the hook's 4-minute Java steps have no staged file in scope. gitleaks (host 8.30.1, the hook image's version) and `sync.mjs check` are run by hand first.
</tradeoffs>
