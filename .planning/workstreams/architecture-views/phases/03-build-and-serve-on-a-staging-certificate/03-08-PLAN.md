## Non-obvious trade-offs
- **Security:** the reworded step publishes the token's real reach: the production-environment jobs of three workflows. The workflow files are public, so nothing new is disclosed. The new text is also the accurate statement: the two-job split fences the token within this workflow, not across the repository.
- **State invalidation:** `sync.mjs check` never reads prose (LikeC4 validates syntax and the drift rules only). The evidence row is the only standing tie. No row of `docs/architecture/drills.tsv` touches the edited lines (`rg` over drills.tsv, drill.fish and sync.mjs found nothing), so the drill replay is not re-run.
- **Live site lags the commit:** the staging host serves the old sentences until a push to main. That push starts `architecture-site.yml` (`docs/architecture/model/**`, lines 24-28) and not `deploy.yml` (`docs/**` and `.planning/**` are in its `paths-ignore`, lines 18-21). It costs one site run and one Flux bump, and it carries the 6 local commits already ahead of origin/main at planning time. This plan does not push: that is the user's call.
- **Rendered size:** step 4's label grows. DIAGRAM_CONVENTIONS.md records publish-the-site at 2360 x 1401 and delivery at 2342 x 1573, both dated 2026-10-28, without a verdict, and the legibility rule is undefined. They are not re-measured here, and the SUMMARY says so.
- **Performance and memory:** none at runtime. Each task's local build writes about 6.7 MB to the gitignored `docs/architecture/site/out`, and the task trashes it.
- **`--no-verify`:** the hook's 4-minute Java steps have no staged file in scope. gitleaks (host 8.30.1, the hook image's version) and `sync.mjs check` are run by hand first.
</tradeoffs>
