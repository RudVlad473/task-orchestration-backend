## Non-obvious trade-offs
- **Performance:** the placement walk is linear in the parsed documents (about 100) plus one pass over each kustomization's `resources`, with a seen set so a cyclic reference cannot loop. Each drill is one check (research measured 1.08 s), so a recording of about 24 sections takes roughly half a minute, twice per task (estimated from the per-check figure, not measured).
- **Memory:** nothing beyond plan 01's parsed document list and the computed model already in memory.
- **State invalidation:** placement is recomputed from the working tree on every check. An element that switches its anchor between `workload` and `source` changes which documents place it, which is why A1, A8 and A9 are rated costly.
- **Security:** `resources` entries that resolve outside `k8s/` are ignored (T-01-04); only documents already parsed from `<root>/k8s` are consulted.

## Planner assumptions recorded (not user decisions)
- A1 (from 01-01): placement as per-element set equality, skipping elements with no k8s anchor. Rated costly. The skip is accepted explicitly as A12 below.
- A8: a HelmRelease is placed in its `spec.targetNamespace` when set, else its `metadata.namespace`; a kustomization-level `namespace` still applies to other kinds as before. Decided by the orchestrator in plan revision, because targetNamespace is where the chart's workloads run, which is what a Physical view shows. "Else its metadata.namespace" is read as kustomize applies it: an inheriting kustomization's namespace is what kustomize writes into metadata.namespace, so a HelmRelease without targetNamespace uses the same inherited-first order as every kind. targetNamespace wins over an inherited namespace, since kustomize rewrites metadata.namespace and not spec.targetNamespace; no manifest in the repo combines the two today. Rated costly: Phase 2's cert-manager element (PHYS-04) and any monitoring HelmRelease element are shaped against it.
- A9: documents whose apiVersion starts `source.toolkit.fluxcd.io/` place nothing. They tell Flux where to fetch a chart or a repository, sit in flux-system by convention, and say nothing about where workloads run. Rated costly for the same reason as A8. Without A9 the real k8s/platform/cert-manager anchor resolves to [cert-manager,flux-system] and D16b is red.
- Three limits of the placement rule are accepted, not checked: this plan adds no rule and no drill for any of them. 01-03 Task 3 states each in the standard's Checks section, and acceptance greps hold that wording.
  - A10 (from 01-01), rated costly: a Flux Kustomization's `spec.targetNamespace` is not modelled. The resolver follows only a kustomize.config.k8s.io Kustomization's `namespace`, so a directory a kustomize.toolkit.fluxcd.io Kustomization applies with `spec.targetNamespace` is placed by its own kustomization and `metadata.namespace` values. Measured 2026-10-27: none of the 9 Flux Kustomizations under k8s/flux-system sets one. Before Phase 2 anchors an element on a directory applied by such a Kustomization, it models the field or records that element in the standard as not placement-checked.
  - A11, rated costly: HelmRelease placement checks the declared `spec.targetNamespace` (A8), never the rendered chart. Chart contents are not parsed, so an object a chart creates outside its targetNamespace is invisible to the check. Phase 2's cert-manager and monitoring elements are placed by what their HelmRelease declares, not by what the chart deploys.
  - A12, rated costly: an element with no anchor document (no `workload` metadata and no `source` under `k8s/`) is not placement-checked, so a moved instance of it passes. Accepted for Phase 2 explicitly: each element Phase 2 adds to the Physical view carries a `workload` or `k8s/` `source` anchor, or the standard's Checks section records it as not placement-checked. Phase 1's real model has no such element: the five elements with instances (traefik, kanban, redpanda, postgres, backup) are all anchored.
- HelmRelease-versus-chart-workload granularity is no longer open for placement: once GATE-01 (Phase 2) adds HelmRelease to the workload kinds, an element carrying `workload 'HelmRelease/<name>'` anchors exactly that document and A8 places it the same way.
</tradeoffs>
