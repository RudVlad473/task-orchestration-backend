## Approaches considered (project directive: decided before this PLAN.md)

How D-03's drill row and hook self-test case fit a scan of a built directory (research Open Question 1):

| Approach | Pros / Cons | Why picked |
|---|---|---|
| Picked: a `scan` drill kind that builds the scratch model and scans it, plus a hook step that runs the scan's fixture tests, held by self-test case 20 | Pro: D-03 as written (drill row, regenerated record, hook case); the hook step is about a second and the drill run gains two builds (about a minute); the record shows sync.mjs alone missing the plant. Con: a second runner path in drill.fish and one more hook step to maintain. | D-03 is a locked decision; the research suggested fixture tests plus one plant and a pull-request run with no drill row and no hook case. Using D-03 per user decision; the fixture tests from plan 01 become the hook's fast input, so the hook gates the scan's logic without building the site. |
| Fixture tests, one recorded plant and a pull-request run only (research recommendation) | Pro: no new harness. Con: no drill row and no hook case, against D-03. | Rejected: contradicts a locked decision. |
| A hook step that builds the site and scans it | Pro: the hook would see the artifact. Con: a 26-second build on every model commit and a likec4 build inside a hook, which research PITFALLS 12 forbids. | Rejected. |

## Non-obvious trade-offs
- **Record stability.** LikeC4 builds are not byte-reproducible and asset names are hashed, so the drill prints only the scan's exit and its last line (`OK targets=13` or `LEAK targets=<names>`), never file names or byte counts; otherwise drill-output.txt would change on every regeneration.
- **What the hook proves.** The hook cannot see a built site, so it proves the scan's logic still catches each target, not that the current model is clean; the model-is-clean claim stays with CI's scan step. The hook header says so.
- **Placement in the hook.** Inside the existing LikeC4 block, after the drift check, so it runs only for commits that already need Node and the install, and before the four-minute Gradle gates.
</tradeoffs>

Data flow in three sentences: drill.fish copies the repo facts and the model into a scratch root, applies the row's edit, and for a `scan` row builds that scratch model with the installed likec4 and runs leak-scan.mjs on the output, printing the exit and last line.
