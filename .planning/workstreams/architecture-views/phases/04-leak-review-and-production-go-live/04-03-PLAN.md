## Approaches considered (project directive: decided before this PLAN.md)

Order of the main push and the pull-request proof:

| Approach | Pros / Cons | Why picked |
|---|---|---|
| Picked: push main first, then the draft pull request from the pushed tip | Pro: the pull request's diff is the one planted line, so its red run is attributable to the plant alone; the scan already gates main. Con: if CI's bytes trip a target that the local build did not (research A6), main's site run fails and nothing is published until a fix, which is a safe failure. | Clean evidence; the local proof already exists. |
| Pull request from local main before pushing | Pro: CI sees the scan before main does. Con: the pull request carries every unpushed commit, so its red run mixes the plant with the whole phase. | Rejected. |

What the owner reviews (D-06):

| Approach | Pros / Cons | Why picked |
|---|---|---|
| Picked: the CI scan report of the push's run plus the live staging site at the rolled tag | Pro: the reviewed bytes are the bytes that go live (same tag, same pod); the flip changes only the certificate. Con: the owner clicks through a staging certificate warning. | D-06 as written. |
| A local build reviewed in a browser | Pro: no warning page. Con: builds are not byte-reproducible, so the reviewed artifact is not the served one. | Rejected. |

## Non-obvious trade-offs
- **Side effect of the push.** `.github/**`, `scripts/**` and `.githooks/**` are not in deploy.yml's `paths-ignore`, so this push runs the whole app pipeline: tests, two image pushes, the Flyway checks, and Flux rolls kanban-prod and kanban-nonprod onto a rebuilt image of unchanged code with the Recreate strategy. Q1 states it.
- **Approval validity.** Any later site build makes a new tag that Flux rolls; plan 04 compares tags, so a stale approval cannot slip through. After this plan only `k8s/**`, `docs/*.md`, `README.md` and `uptime-check.yml` may change, none of which is a site trigger.
- **Public traces of the proof.** The closed pull request, its branch history and its logs stay public, including the made-up private address 10.20.30.40; nothing real is planted.
</tradeoffs>
