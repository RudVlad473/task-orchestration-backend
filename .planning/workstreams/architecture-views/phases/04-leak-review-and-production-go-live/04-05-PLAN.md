## Approaches considered (project directive: decided before this PLAN.md)

The site drill (research Open Question 2):

| Approach | Pros / Cons | Why picked |
|---|---|---|
| Picked: no new input; the drill dispatches the probe on a throwaway branch whose `SITE_MARKER` is wrong, then on main | Pro: no new code path or input to document; the red is attributable to the marker alone because the URL and TLS are the real ones; worst case stays 6 URLs (480 s), inside D-10's 10 minutes. Con: a branch push, and two emails from the alert issue. | Keeps D-10's arithmetic exact and the workflow smaller. |
| A second boolean input `drill_site` (research recommendation) | Pro: re-runnable on demand. Con: 7 URLs (560 s) when both drills are set, leaving 40 s of a 10-minute cap, or mutual-exclusion code; one more input to document. | Rejected: more code for a check that runs once. |
| Extend the existing `drill` input to the site | Pro: one input. Con: changes what a documented input does and cannot separate a marker failure from a URL failure. | Rejected. |

The refresh in D-13:

| Approach | Pros / Cons | Why picked |
|---|---|---|
| Picked: a Playwright reload (`page.reload()`) through shot-scraper's own interpreter, plus the Phase 3 cold-load recipe | Pro: a real refresh, `navigation.type` reads `reload`; no install (Playwright imports there, checked while planning). Con: a short inline program. | Settles research A4 instead of assuming it. |
| Two cold shot-scraper runs | Pro: the existing recipe. Con: a second cold load is assumed, not shown, to equal a refresh. | Kept as the cold-load half only. |

## Non-obvious trade-offs
- **Ordering.** The site entry lands only after the production certificate is Ready: the probe never follows redirects and a staging chain fails TLS with status 000, which would open the alert issue for nothing.
- **App rollout during the push.** `.github` is not in deploy.yml's ignore list, so the push redeploys the app with Recreate; the baseline dispatch waits until prod and nonprod answer 200 again, so its green and the drill's red are attributable.
- **What the probe proves.** nginx serves `index.html` for every extensionless path, so a root probe proves the LikeC4 shell is served, not that its hashed assets load; asset names change per build and cannot be a constant. Recorded as a known hole in the workflow header.
</tradeoffs>
