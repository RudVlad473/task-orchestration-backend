## Non-obvious trade-offs
- **False positives are the real risk.** Loose patterns hit minified vendor code (a shell word list, SVG path numbers, LikeC4 deployment ids such as `k3s.monitoring`, CSS design tokens). The strict forms below were measured at zero hits on the current build; each trap becomes a fixture that must pass, so nobody loosens a pattern later without a red test.
- **Public logs.** The repository is public, so CI logs are public; the report prints the matched text, the file and a count, never the surrounding line (bundles are single lines of hundreds of KB).
- **Cost.** One pass over about 20 files and 6.8 MB, one file in memory at a time; well under a second.
- **Exit code masking.** The step has no pipe: with no `shell:` GitHub runs `bash -e`, and `| tee` would turn a hit into a green step. The script writes `GITHUB_STEP_SUMMARY` itself.
- **Secret names.** Names referenced as Secrets overlap names the model draws on purpose (`letsencrypt-staging`, `flux-system`), so the list is curated from the manifests minus the model's own names, each exclusion recorded.
</tradeoffs>

<objective>
Build the leak scan of the built site, run it in the site workflow before the image exists, prove it red on a planted IP and green on the real build, cover every target with a fixture test, and rewrite the model text that would otherwise go stale after the review.

Data flow in three sentences: `likec4 build` writes the static site to `docs/architecture/site/out`, and the new step reads every file there as bytes and matches 12 target patterns plus a four-host allow-list and a robots.txt check. A hit exits 1, which fails the build job, so the publish job (`needs: build`) never pushes an image and the pull-request run shows the same red with no secret present. The fixture tests spawn the same script on small directories, one per target and trap, so a weakened pattern fails a test before it can pass a real build.

Output: the script, its tests, two workflow steps, the baseline record and three model text fixes with their evidence re-cited.
</objective>

Strict patterns (research Pattern 1, measured at 0 hits on the current build):
- ipv4: `(?<![0-9.])(?:25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])(?:\.(?:25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])){3}(?![0-9])`
- ipv6: `(?<![0-9A-Fa-f:])(?:[0-9A-Fa-f]{1,4}:){3,7}[0-9A-Fa-f]{1,4}(?![0-9A-Fa-f:])` and `(?<![0-9A-Za-z:])(?:[0-9A-Fa-f]{1,4}:){1,6}:(?:[0-9A-Fa-f]{1,4})?(?![0-9A-Za-z:])`
- ssh-command: the literal `ssh` followed by one space. kubectl: the literal. secret-word: `secret`, case-insensitive.
- key-path: `authorized_keys`, `id_ed25519`, `id_rsa`, `~/.ssh`, `/home/`, `/opt/deploy`, `BEGIN [A-Z ]*PRIVATE`, `pass show`. ssh-host: `netcup-prod`.
- credential: `ghp_[A-Za-z0-9]{20}`, `AKIA[0-9A-Z]{16}`, `dckr_pat_`, five dashes followed by `BEGIN`.
- in-cluster-host: `\.svc\b`, `cluster\.local`, `postgres\.kanban`, `PGHOST`.
- secret-name: word-bounded alternation of the curated list from Task 1 step 1.
- hostname: every match of `[A-Za-z0-9.-]*duckdns\.org` that is not one of `kanban-board-rud-vlad-473.duckdns.org`, `kanban-board-rud-vlad-473-nonprod.duckdns.org`, `kanban-board-rud-vlad-473-monitoring.duckdns.org`, `kanban-board-rud-vlad-473-architecture.duckdns.org`.
- robots: `robots.txt` at the root of the directory is missing or has no line equal to `Disallow: /`.
Traps that must never hit: a generic `\bssh\b` (a bundled shell word list), a dotted-quad without boundaries (SVG numbers such as `58.06.87.06`), a generic `<word>.<namespace>` host rule (`k3s.monitoring` and four more LikeC4 deployment ids), `kanban-data` alone, `token`, `password`.
