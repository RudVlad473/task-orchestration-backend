## Non-obvious trade-offs
- **Performance:** the hosts reader is one regex over at most a few dozen match strings; gotk-components.yaml is already parsed by k8sDocs (about 6000 lines), so no new parse.
- **State invalidation:** `production` grows by about eight nodes; its natural width is recorded in plan 05 against the 1965 px it had.
- **Placement coverage:** svclb, the host filter, the firewall, Let's Encrypt, the client and the delivery instances have no k8s anchor, so they are not placement-checked (Phase 1 A12); plan 05 lists them in the standard. The issuers anchor on ClusterIssuer documents that land in no namespace, which matches an instance on the cluster node (research Pattern 3).
- **Security:** the three hostnames are already linked from the README; no IP, SSH forward target or key path is written. The repo element carries no `k8s/` source, because a source on gotk-sync.yaml would anchor it to flux-system while its instance sits on the GitHub provider node.
</tradeoffs>
