## Non-obvious trade-offs
- **Performance:** each new rule is one pass over views, edges or elements (tens of items), well under the 1.4 s check. Four new drills add about 6 s per harness run.
- **State invalidation:** a shared title is now load-bearing: editing one relationship title on a merging pair brings `[...]` back. The label rule is what catches it, at commit time through the hook.
- **Security:** the backup relationship's title named the Postgres Service's in-cluster DNS name; it is replaced here, before Phase 3 publishes the model (Pitfall 8).
- **Open question resolved (research OQ1):** D1-A+ as above. Phase 1 review items: WR-03 is folded in (Task 3), because without it deleting the `instanceOf` of any element this phase adds passes silently. WR-04 (trailing slash on a `k8s/` source) is left open: every element this phase adds anchors by `workload`, so it protects nothing Phase 2 delivers.
</tradeoffs>
