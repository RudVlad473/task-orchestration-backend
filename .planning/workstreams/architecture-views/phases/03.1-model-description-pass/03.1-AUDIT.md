## Population

Command: `node .planning/workstreams/architecture-views/phases/03.1-model-description-pass/03.1-inventory.mjs docs/architecture/model`. It loads the model through LikeC4's computed model, the API that `sync.mjs check` uses, and prints one row per item. At BASE it printed 99 items: 62 elements (42 hand-written, 20 generated), 16 deployment nodes and 21 views. The output at BASE is stored in `03.1-inventory-before.tsv`, and the stored file re-derives from the BASE commit (verify gate in plan 01 Task 1).

The rule is the `**Description.**` bullet in `docs/DIAGRAM_CONVENTIONS.md`, section "Entities and rules". It was written before this audit.

How each item was judged:

- Presence, trailing period and the word cap (35 for an element or deployment node, 70 for a view) come straight from the TSV columns.
- Sentence shape: a description is a sentence or a definition-form noun phrase that names the thing ("Log collector that ships pod logs to Loki."). A bare list of nouns or a colon list is `sentence`. A semicolon between two independent clauses is `sentence` (one fact per sentence). A view that narrates consecutive steps in one sentence is one fact, the trace, and is not flagged. A view whose first sentence is a fragment is flagged.
- Stale: a claim contradicted by a repo file seen while auditing. This is not a fact-check of every claim.

## Generated elements (D-02)

The 20 generated elements (6 tables, 14 packages) get their text from the generator (`sync.mjs generate`, `renderTables` and `renderPackages`), which lands in plan 03. An authored overlay is impossible: `extend postgres.table_users { description '...' }` fails to parse at likec4 1.60.0 ("Expecting token of type '}' but found 'description'", research Q3, run). Editing `generated.c4` by hand is refused by its header and by the stale check, which compares `render()` with the file byte for byte. A generator template stating where the element was read from keeps hook self-test case 6, which adds a table and regenerates, green. These rows carry the fix `generator`.

## Not audited

- Relationships (D-02): they keep their label as their only text, under the protocol-level rule.
- Deployment instances: they inherit the description of their element, so they cannot be missing one on their own.
- Existing leak-scan identifiers: a rewrite keeps a name already in that item's BASE text (`kanban-data`, `KANBAN-INGRESS`, repo paths such as `infra/vm/k3s/install.sh`) and adds none. Removing them is Phase 4's scan.
- Property order inside element blocks (D-04): not prescribed, not changed.
