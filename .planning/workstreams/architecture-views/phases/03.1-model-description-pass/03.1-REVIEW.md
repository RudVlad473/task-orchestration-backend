## Warnings

### WR-01: The word cap, sentence shape and leak clause are "held by review", but no review step or tool checks them

**File:** `docs/DIAGRAM_CONVENTIONS.md:117-120`, `docs/architecture/sync.mjs:518-537`
**Issue:**
- The Description bullet says "The cap, the sentence shape and the leak clause are held by review", and the cap is defined mechanically ("Words are counted by splitting on whitespace").
- No review artifact covers it. `docs/CODE_REVIEW_RUBRIC.md` and the `code-review-rubric` skill are scoped to Java, and neither mentions `DIAGRAM_CONVENTIONS.md`.
- The only tool that counts words is `.planning/.../03.1-inventory.mjs`, which sits in a phase directory and is wired to nothing.
- The cap was the defect that actually occurred: 4 items were over it at BASE (`error-401` at 263 words, `monitoring` at 131). The first edit to a view description can reintroduce it, and `sync.mjs check` stays green.
- The "held by review" sentence therefore describes a gate that does not exist.

**Fix:** Add the cap to `checkDescriptions`, since the counting rule is already one line:
```js
const cap = surface === 'view' ? 70 : 35
const words = text.split(/\s+/).length
if (words > cap) problems.push(`${surface} ${item.id} description has ${words} words, over the cap of ${cap}`)
```
Add one drill row for it (an over-cap description edited into the scratch copy). If the cap is deliberately left out, change the doc to say "not enforced" instead of "held by review".

### WR-02: `checkDescriptions` accepts any text that ends in a period, so a placeholder defeats the presence guard

**File:** `docs/architecture/sync.mjs:530-533`
**Issue:**
- The presence test is `text === ''` and the shape test is `endsWith('.')`.
- A description of `.`, `TODO.` or `Authored.` satisfies both. The doc names `Authored.` as an optional provenance opener, not as a whole description.
- `DIAGRAM_CONVENTIONS.md:117` says `sync.mjs check` "refuses an Element, deployment node or View with no description". A one-token placeholder passes that gate, and a contributor who hits the new refusal can silence it without writing anything.
- The drills (D28 to D28d) only delete a description or its period, so none of them would notice.

**Fix:** Require at least a few words, for example:
```js
else if (text.split(/\s+/).length < 3 || !text.endsWith('.')) problems.push(...)
```
Otherwise reject a text equal to `Authored.`. Add a drill row that sets a description to `TODO.`.

### WR-03: The self-test docstring still describes 16 cases

**File:** `scripts/pre-commit-likec4-selftest.py:3-4`

### IN-01: The "full sentences" rule and the accepted noun-phrase descriptions disagree

**File:** `docs/DIAGRAM_CONVENTIONS.md:104-107`, `docs/architecture/model/monitoring.c4:11`
**Issue:**
- The rule says "full sentences" with the thing as subject, and gives definition-form phrases with a relative clause ("Log collector that ships pod logs to Loki.") as passing examples.
- Several descriptions are verbless noun phrases with no relative clause: `grafana` ("Dashboards over the Prometheus and Loki datasources."), `redpanda` ("Kafka-compatible broker, one per environment."), `kanban` ("Spring Boot REST API with session auth and per-user ownership checks."), and `postgres` ("Single instance in ns kanban-data, holding ..."), which also uses the abbreviation `ns`.
- `github.runner` (`delivery.c4:59`) has the architecture as its subject, not the runner.
- Because the sentence shape is review-only (WR-01), a reviewer cannot tell from the rule whether these pass.

**Fix:** State in the rule that a noun phrase with an appositive or participle passes. Otherwise reword these five, for example "Serves dashboards over the Prometheus and Loki datasources."

### IN-02: `order` numbers are one global sequence across three files, and nothing checks them

**File:** `docs/architecture/model/scenarios-app.c4` (1, 5-8), `docs/architecture/model/views.c4` (2-4), `docs/architecture/model/scenarios-platform.c4` (9-14)
**Issue:**
- The 14 scenario `order` values are interleaved across three files. Adding or moving a scenario means renumbering other files.
