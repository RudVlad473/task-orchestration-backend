## Planning assumptions (orchestrator-resolved open questions, taken from the research)

1. Generated elements get provenance-only text from a generator template (above).
2. The D-01 rule stays as CONTEXT states it. LikeC4's `summary` is mentioned as optional only: it parses on elements and nodes, not on views.
3. Caps are 35 and 70 words (above).
4. The cap is enforced by the audit only. The script rule covers presence and the trailing period.
5. D-04: no property order is prescribed and none is changed. The invariance gate holds that every non-description line is unchanged.
6. The audit is not a fact-check of every claim. A claim seen contradicted by a repo file while auditing gets class `stale` with the contradicting file:line, and is fixed. One is known from planning: `certmanager.staging` (edge.c4:10) says no Certificate references the staging issuer, but k8s/overlays/architecture/certificate.yaml:13 names letsencrypt-staging.
7. Commits use `--no-verify`, because none stages Java, a migration or a k8s manifest (project CLAUDE.md). The hook steps that read these paths (gitleaks, comment lint, `sync.mjs check`) are run by hand first. spotlessCheck and fastTest have no file in scope.
8. Existing names stay until Phase 4 (CONTEXT out-of-scope clause). The audit does not hunt leak-scan identifiers, so it has no leak class. A rewritten description may keep a name already in its own BASE text, for example `kanban-data` in the `postgres` description or `KANBAN-INGRESS` on the `netcup` node. It must add none. The leak gate holds the "add none" half: at BASE its patterns match no description line, only the four host metadata lines in model.c4, so a rewrite that keeps existing text cannot trip it.
9. Deployment-node descriptions are in plan 02 (Task 3), not here. The D11 and `certmgr_into` anchor fix must land in the same commit as the namespace descriptions. The reworked anchors insert after the description line. Before that line exists they would put certmgr outside its namespace block, because sed's `n` steps onto the closing brace of the empty flux-system and cert-manager nodes. That is read from the sed program; it was not run. Moving the pair keeps this plan within 10 files (checker revision, scope_sanity).

## Non-obvious trade-offs

- **Public exposure:** every description is published on the staging-certificate site at the next push to main, because model/** triggers architecture-site.yml. The leak gate refuses any added model line matching the Phase 4 scan targets (hostnames, IPs, Secret names found under k8s, key paths, in-cluster service names, `kubectl`, `ssh `). Existing text is left to Phase 4, per the phase boundary.
- **Layout:** descriptions render inside diagram nodes, so text changes widen or narrow views a little. The dated size tables in DIAGRAM_CONVENTIONS.md are not re-measured. The SUMMARY says so.
- **Drill anchors (measured while planning):** a `description` after an `instanceOf` in a deployment node fails to parse ("Expecting token of type '}' but found `description`"). Drill D11 and the `certmgr_into` helper insert an `instanceOf` right after a namespace header, so with namespace descriptions in place D11, D16 and the control D16b break. Plan 02 Task 3 adds the namespace descriptions and moves the insert to after the description line, in one commit. A probe of the reworked anchors reproduced the recorded D11, D16 and D16b output. This plan adds no namespace description, so the drills are untouched here.
- **Performance:** none at runtime. The inventory loads the model once (about 3 s), and the build gate takes about 10 s. Estimate check (`gsd_run query estimate-check --tokens 75000 --calibrated`, 2026-10-29): budget 100000, ratio 0.75, not over budget, calibration factor 1 from 0 samples, confidence low.
</tradeoffs>

Then fix every hand-written element defect the audit lists. View and deployment-node defects are fixed in plan 02, and generated elements in plan 03.

Data flow in three sentences: the inventory script loads the model through LikeC4's computed model, the same API `sync.mjs check` uses, and prints one TSV row per element, deployment node and view, with word count and trailing-period flag. The audit reads that TSV and the rule and writes, per defective item, the exact replacement text. The model edits copy that text, and the audit-text gate re-runs the inventory to prove the model now says what the audit says.

Output: the rule, the inventory script and its BASE TSV, the audit, the netcup.k3s description (tracer), and corrected element descriptions in model.c4, edge.c4, delivery.c4 and monitoring.c4.
